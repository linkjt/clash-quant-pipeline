# clash-quant-pipeline

## The Premise
Clash Royale is a competitive video game where players go head-to-head placing cards strategically in order to try to destroy the opponents princess and king towers.
In clash royale, players can choose from 171 different cards to build an 8 card deck. There are over 7.4 trillion possible deck combinations. It is computationally impossible to store data about every single deck. Sites like RoyaleAPI and StatRoyale attempt to track deck winrates, however slight modifications for decks could drastically impact winrates. Additionally, even if individual decks are tracked, there is no guarantee there will be enough games for a deck on a specific day where there are modification made. Additionally, it is impossible to get the win rate of both decks and cards for today, as the only way we can accurately gauge the full data of games is if we are looking backwords. ie. every site has winrates for the past day the past three days ect. None of them have winrates for today. The answer is to overthink it.

This is liquidity. Its clash royale equivalent is the usage rate. My idea of this analysis is that clash royale analysis is like stock analysis. It started with quantitative, companies' new products; cards, new buffs, merges; reworks. But then it moved into quant, and that is the standard. ## Implementation

### Data Collection
It begins by grabbing raw matches from clash royale's api. The method I use is mass collecting every single game in the past 30 days, although this does skew towards what is shown by a deck, the law of numbers says that having more is overall better. Then I find one random match and look at that person's opponent and then do the same for their games. In this process I save all games to a sql database so I don't save any duplicates and I create match ids that correspond to each match so that neither of the matches from the opponents game is put in as a new match.
### Data Processing
Then I go through every single match with a different script that translates the matches straight into games played and games won for every card for every day. This is much better than calculating winrates as that would be doing repeated multiplication and this simplifies it down to addition. Here I also differentiate between Evolutions and heros. Additionally I also create a table of total cards played for that day to get usage rates for later on.
### Data Analysis
This is what's novel. I start out by creating a bunch of indicators, RSI, ROC, Sharpe Ratio, Beta, Drawdown, and more. This is really simple stuff that I just use for creating the preliminary first step to the more complicated math. I also created a correlation matrix of all cards based purely on winrate to mathematically find synergies. This is used for what is called in quant pair divergence and pair convergences. Basically two correlated cards should have winrates that stick together, and drifting between them will eventually result in reversion. These correlations are then also used to create 6 different card clusters of correlated cards which are huge in predicting trends in winrates. Additionally I have two predictive models that are both really simple, Geometric Brownian Motion and Ornstein-Uhlenbeck Process, they sound complicated but they just are monte carlo simulations where they only have the past volatility and use that. The only difference is the GBM is not meant reverting and the OU is mean reverting. They are often wrong and their predictions are useless for short term and since its mean reverting is really just random long term. As a result I use a bit more complicated math for the next step, Machine Learning. I have two models that I use, XGBoost and LSTM. XGBoost is a classification model and I use the LSTM for regression. The XGBoost is trained on all cards all at once and predicts whether or not the cards' win rate will be higher tomorrow utilizing all of the different quant metrics that I have created. It is accurate over 70% of the time. In quant that would be insane. However it is useless if a card's winrate is high if we can't figure out the actual winrate, which is what the LSTM does. It uses a very similar feature table but it is trained on a 7 day window. One of the big things is that both of these things are predicting based on everything up until yesterday, so they predict for today, effectively giving us today's win rate. This solves the first major problem with all of those sites and additionally all of these indicators help us with other stuff. Say you are a new player, you want to spend your gold on good long term cards, those cards can be mathematically found.
